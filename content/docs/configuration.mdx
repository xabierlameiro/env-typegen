## Config file

Create `env-typegen.config.mjs` at your project root:

```typescript
import { defineConfig } from "@xlameiro/env-typegen";

export default defineConfig({
  version: 1,
  input: ".env.example",
  output: "env.generated.ts",
  generators: ["typescript", "zod"],
  format: true,
  schemaFile: "env.contract.mjs",
  strict: true,
  diffTargets: [".env", ".env.example", ".env.production"],
  providers: {
    vercel: {
      adapter: "./src/adapters/vercel-adapter.ts",
      projectId: "project_123",
      token: "${VERCEL_TOKEN}",
    },
  },
  environments: {
    development: { source: "local" },
    preview: { source: "vercel", targets: ["preview"] },
    production: { source: "vercel", targets: ["production"] },
  },
  rules: {
    strict: true,
    allowExtra: false,
    requireAll: true,
  },
  plugins: ["./plugins/custom-validator.mjs"],
});
```

For direct Node.js runtime execution, prefer `.mjs` or `.js` config files.
TypeScript config files (`.ts`) require a runtime loader such as `tsx` or `ts-node`.

## Advanced config options

### `providers`

Registers adapter-backed providers for `pull` and governance workflows.

```typescript
export default defineConfig({
  providers: {
    vercel: {
      adapter: "./src/adapters/vercel-adapter.ts",
      projectId: "project_123",
      token: process.env.VERCEL_TOKEN,
    },
  },
});
```

### `environments`

Maps logical environments to source providers and target aliases.

```typescript
export default defineConfig({
  environments: {
    development: { source: "local" },
    preview: { source: "vercel", targets: ["preview"] },
    production: { source: "vercel", targets: ["production"] },
  },
});
```

### `rules`

Defines governance policy defaults globally and by environment.

```typescript
export default defineConfig({
  rules: {
    strict: true,
    allowExtra: false,
    requireAll: true,
    perEnvironment: {
      development: { allowExtra: true },
      production: { strict: true, allowExtra: false, requireAll: true },
    },
  },
});
```

### `schemaMode`

Controls how env-typegen resolves type information when a contract is present.

- `legacy` (default): inference-first behavior with annotation overrides.
- `contract-first`: the contract becomes authoritative; inference is used as fallback only.

```typescript
export default defineConfig({
  input: ".env.example",
  schemaFile: "env.contract.mjs",
  schemaMode: "contract-first",
});
```

### `inferenceRules`

Adds custom type inference rules before built-in rules. Rules are evaluated in ascending `priority` order (lower number runs first).

```typescript
export default defineConfig({
  input: ".env.example",
  inferenceRules: [
    {
      type: "string",
      priority: 5,
      match(key, value) {
        return key.endsWith("_TOKEN") && value.length > 0;
      },
    },
  ],
});
```

```typescript
export default defineConfig({
```


## Generate command flags

CLI flags override config file values when both are provided.

`--format` is the preferred generator flag. `--generator` is kept as a
backward-compatible alias for existing scripts.

| Flag          | Alias | Description                                    |
| ------------- | ----- | ---------------------------------------------- |
| `--input`     | `-i`  | Path to `.env.example` file(s). Repeatable     |
| `--output`    | `-o`  | Output file path                               |
| `--format`    | `-f`  | Generator(s): `ts`, `zod`, `t3`, `declaration` |
| `--generator` | `-g`  | Alias for `--format`                           |
| `--stdout`    |       | Write output to stdout instead of a file       |
| `--dry-run`   |       | Preview output without writing files           |
| `--no-format` |       | Skip Prettier formatting of output             |
| `--silent`    | `-s`  | Suppress success logs                          |
| `--watch`     | `-w`  | Re-generate on file changes                    |
| `--config`    | `-c`  | Path to config file                            |
| `--version`   | `-v`  | Print version                                  |
| `--help`      | `-h`  | Show help                                      |

## Validation command flags (`check`, `diff`, `doctor`, `verify`)

| Flag                      | Commands                    | Description                                                          |
| ------------------------- | --------------------------- | -------------------------------------------------------------------- |
| `--env <path>`            | `check`, `doctor`, `verify` | Environment source path to validate                                  |
| `--targets <list>`        | `diff`, `doctor`, `verify`  | Comma-separated env targets for drift analysis                       |
| `--contract <path>`       | all                         | Contract file path (`env.contract.mjs` / `.js` / `.ts`)              |
| `--example <path>`        | all                         | Fallback `.env.example` used when no contract file is available      |
| `--strict`                | all                         | Validate extras as errors (default behavior)                         |
| `--no-strict`             | all                         | Downgrade undeclared variables to warnings                           |
| `--json`                  | all                         | Emit compact machine-readable JSON report                            |
| `--json=compact`          | all                         | Explicit alias of `--json` (compact machine-readable JSON)           |
| `--json=pretty`           | all                         | Emit pretty JSON report                                              |
| `--output-file <path>`    | all                         | Persist JSON report to file                                          |
| `--debug-values`          | all                         | Include raw values in issues (unsafe for CI logs)                    |
| `--cloud-provider <name>` | all                         | Add cloud snapshot source: `vercel`, `cloudflare`, `aws`             |
| `--cloud-file <path>`     | all                         | Cloud snapshot JSON file path                                        |
| `--plugin <path>`         | all                         | Plugin module path (repeatable). Module must export a `name` string. |
| `--config <path>`         | all                         | Config file path                                                     |
| `--help`                  | all                         | Show command help                                                    |

## Plugin contract

Plugins are plain ESM modules with a default export matching the `EnvTypegenPlugin` shape:

```typescript
export default {
  name: "my-plugin", // required

  transformSource({ environment, values }) {
    // optional — mutate or replace per-environment values before validation
    return values;
  },

  transformContract(contract) {
    // optional — mutate or replace the loaded contract before validation
    return contract;
  },

  transformReport(report) {
    // optional — post-process the validation report
    return report;
  },
};
```

> The `name` field is **required**. Plugins without it are rejected at startup with a descriptive error.

Register plugins via CLI or config file:

```bash
env-typegen check --env .env --contract env.contract.mjs --plugin ./plugins/my-plugin.mjs
```

```typescript
export default defineConfig({
  plugins: ["./plugins/my-plugin.mjs"],
});
```

## Precedence model

1. CLI flags (highest priority)
2. Config file values
3. Built-in defaults

## Defaults and path resolution

- Strict mode is enabled by default for validation commands.
- `diff` defaults to `.env,.env.production` when targets are not provided.
- When `--contract` is omitted, env-typegen auto-discovers `env.contract.mjs` or `env.contract.js`.
- All paths are resolved from your current working directory.

## Configuration type reference

The sub-types that compose `EnvTypegenConfig`. The package entry point exports
`EnvTypegenConfig` and `GeneratorName`. Reach any other sub-type through an indexed access:

```typescript
import type { EnvTypegenConfig } from "@xlameiro/env-typegen";

type WritePolicy = NonNullable<EnvTypegenConfig["writePolicy"]>;
```

### `EnvTypegenProviderConfig`

Shape of each entry in the `providers` map:

```typescript
type EnvTypegenProviderConfig = {
  adapter: string; // Path to the provider adapter module
  token?: string; // Auth token (supports ${ENV_VAR} interpolation)
  projectId?: string; // Provider project identifier
  options?: Record<string, unknown>; // Adapter-specific options
};
```

### `EnvTypegenEnvironmentConfig`

Shape of each entry in the `environments` map:

```typescript
type EnvTypegenEnvironmentConfig = {
  source: string | string[]; // Provider key, "local", or a chain of sources
  targets?: string[]; // Provider-specific target alias(es)
  metadata?: Record<string, unknown>; // Provider-specific extension point
};
```

### `EnvTypegenRuleSet`

Base validation policy rules. Used directly in `rules` or as values in `perEnvironment`:

```typescript
type EnvTypegenRuleSet = {
  strict?: boolean; // Treat undeclared vars as errors (default: true)
  allowExtra?: boolean; // Allow vars not in contract (overrides strict for extras)
  requireAll?: boolean; // Require all contract vars to be present
};
```

### `EnvTypegenRulesConfig`

Extends `EnvTypegenRuleSet` with optional per-environment overrides:

```typescript
type EnvTypegenRulesConfig = EnvTypegenRuleSet & {
  perEnvironment?: Record<string, EnvTypegenRuleSet>;
};
```

### `EnvTypegenPolicyPackLockConfig`

Controls lockfile integrity for installed policy packs:

```typescript
type EnvTypegenPolicyPackLockConfig = {
  path?: string; // Path to the lock file used by policy pack resolution
  strict?: boolean; // Fail when a referenced pack has no lock entry (default: true)
};
```

### `EnvTypegenPolicyPackFetchConfig`

Controls remote pack fetch behavior:

```typescript
type EnvTypegenPolicyPackFetchConfig = {
  timeoutMs?: number; // HTTP fetch timeout in milliseconds
  maxRetries?: number; // Retry count on network errors
  retryDelayMs?: number; // Delay between retries
  cacheTtlMs?: number; // Time-to-live for cached pack responses
  cacheDir?: string; // Local cache directory path
  offline?: boolean; // Disable remote fetch; use cache only
};
```

### `EnvTypegenPolicyPackTrustConfig`

Controls signature trust validation for policy packs:

```typescript
type EnvTypegenPolicyPackTrustConfig = {
  mode?: "strict" | "tolerant"; // strict blocks missing or invalid signatures, tolerant allows unsigned packs
  allowedSigners?: string[]; // Allowed signer identifiers
  enforceExpiry?: boolean; // Reject packs with expired signatures
  externalTrustRoot?: {
    provider: "aws-kms" | "gcp-kms" | "hashicorp-vault" | "external";
    keyringPath?: string; // Keyring document used as the trust root source
  };
};
```

### `EnvTypegenPolicyDistributionConfig`

Controls policy distribution channel and sink for governance rollout:

```typescript
type EnvTypegenPolicyDistributionConfig = {
  channel?: PolicyDistributionChannel; // "dev" | "stage" | "prod"
  sink?: PolicyDistributionSink; // "local" | "s3" | "github-packages"
  destination?: string; // Sink-specific target path or URL
};
```

See the [Policy Packs](/docs/policy-packs) page for promotion channel rules.

### `EnvTypegenTemplatesConfig`

Default values used during multi-repo bootstrap orchestration:

```typescript
type EnvTypegenTemplatesConfig = {
  defaultTemplate?: "web-app" | "library"; // Used when a fleet manifest entry omits `template`
  defaultEnforcementLevel?: "advisory" | "standard" | "strict";
  defaultPolicyChannel?: "dev" | "stage" | "prod";
};
```

### `EnvTypegenWritePolicyConfig`

Write controls for `sync-apply` runtime behavior:

```typescript
type EnvTypegenWritePolicyConfig = {
  enableApply?: boolean; // Master switch for write operations
  protectedEnvironments?: string[]; // Environments that require protected branch execution
  requirePreflight?: boolean; // Require preflight report before apply
  auditLogPath?: string; // Path to write the apply audit log
  // executionBudget, sloPolicy, incidentState — see Operations and
  // Governance Chaos and SLO pages for their shapes and usage
};
```

> `executionBudget`, `sloPolicy`, and `incidentState` reference governance-layer
> types that are not re-exported from the main package entry point.
> See [Operations](/docs/operations) and [Governance Chaos and SLO](/docs/governance-chaos-and-slo)
> for their shapes and usage.

## FAQ

### Should I always commit `env-typegen.config.mjs`?

Yes for team consistency. It centralizes defaults and reduces CI/local mismatch.

### Can I use different configs per command?

Yes. Use `--config <path>` to load command-specific configuration files.
